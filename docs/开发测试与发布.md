# Boplet 开发、测试与发布

本文件维护可执行流程；进度只记在[开发计划](产品图标工坊-开发计划.md)。安装、启动、测试、提交、发布与部署是不同操作，不因前一步成功自动执行下一步。

## 分发约定

- 唯一源码仓库：`https://github.com/walnut-a/boplet-icon-studio`。不使用 npm 分发；`package.json` 的 `private:true` 保留。npm 仅用于开发时安装依赖和运行脚本。
- 普通用户从此仓库的 GitHub Release 获取完整 `make-product-icons-<版本>.zip`，同时读取 `release.json` 和 `sha256.txt`。包内包含方法论、网页、运行时、合同及许可证，不需要用户安装 npm 依赖。
- 用户也可以直接拉取仓库，在固定 tag/commit 上按 README 构建再安装。原始 `skill/` 是源码，不能直接安装；无需为 GitHub 安装把编译产物提交到主分支。
- 官网“复制本地指令”继续读取 `/downloads/release.json`。GitHub Release 可公开下载后，官网构建将该清单指向同一 GitHub ZIP；在线方法论也来自同一候选。无需维护第二份用户安装指令。
- 仓库未公开或 Release 尚未发布时，保留已有网站预览包入口。候选清单的 GitHub URL 是计划地址，不证明发布成功。更新提示源仍未启用，不新增自动安装或追踪主分支覆盖。

## 管线与身份

```text
源码 + 锁定依赖
  → 单元/合同/集成测试 + 浏览器回归
  → 唯一发布候选（完整 Skill、ZIP、SHA-256、release.json）
      ├─ 隔离安装 → 本地运行/离线重开/导出验收
      ├─ GitHub Release 附件（另行授权发布）
      └─ 官网构建复用候选 → Cloudflare（另行授权部署）
```

`version` 是版本号，`buildId` 是包清单哈希，`sha256` 是 ZIP 哈希。版本号相同不代表内容相同。发布使用干净、已提交并打 tag 的源码；验收后不重建或覆盖该版本附件，有修改就准备新候选/新版本。

## 1. 日常开发与自动测试

Node.js 22.23.1–22.x；测试机安装 Google Chrome。

```sh
npm ci --ignore-scripts
npm test
npm run build
npm run test:e2e
```

`npm test` 包含合同、核心、服务、安装与独立离线包测试。`test:e2e` 顺序执行本地页面、规模、浏览器存储、官网、查看及在线流程回归。测试使用合成数据、临时安装和隔离配置，测试结束关闭自己启动的服务；不用真实图标目录。

## 2. 本机三种预览不要混用

| 目的 | 入口 | 注意 |
| --- | --- | --- |
| 官网排版及 `/studio/` 浏览器测试 | `npm run build:web`，静态服务 `dist/web` | 只构建页面，不更新下载包；浏览器目录能力与 WebMCP 分别检查 |
| 仓库源码开发容器 | `npm run build`，`node scripts/preview.js <授权目录>` | 需要真实 HTML 同意环境变量；build ID 明确标为 repository-development |
| 用户安装包验收 | 候选包 `runtime/start.mjs` | 脱离仓库运行，对比回执版本/build ID，不能继续看旧端口 |

静态服务示例：`python3 -m http.server 53058 --bind 127.0.0.1 --directory dist/web`。端口冲突时换端口，不杀未知进程。

交互验收请为本轮新建独立的合成数据目录和配置目录。通过 `ICON_STUDIO_CONFIG_DIRECTORY` 隔离配置；使用包内 runtime 说明，在用户明确允许 HTML 后填写真实同意引用。自动化测试内的合成同意不是实际使用的授权。

## 3. 生成与验收候选

日常打包可以指定新输出目录，避免清空旧候选：

```sh
npm run pack:skill -- --output outputs/local-check-001
npm run check:package -- --output outputs/local-check-001
```

用于发布的候选（下面版本必须与 package.json 一致）：

```sh
npm run prepare:release -- outputs/release-0.1.0-dev.2 v0.1.0-dev.2
npm run check:release -- outputs/release-0.1.0-dev.2
```

对该候选运行脱离仓库的安装、启动、合成图标导出、离线重开及卸载保留数据验收（只复制候选到临时目录，不修改候选或实际安装）：

```sh
BOPLET_TEST_SKILL=outputs/release-0.1.0-dev.2/skill node --test tests/integration/package.test.js
```

输出目录必须为空；失败时保留现场，换新候选目录，不盲目清理。`check:release` 检查清单、包内文件、ZIP 字节、哈希和 GitHub 下载地址一致性，**不访问 GitHub，也不发布**。

本机检查和安装均显式传目录。最后一个候选参数可省略，省略时构建当前源码；发布验收请不要省略。

```sh
npm run check:installed -- /absolute/test-skills/make-product-icons outputs/release-0.1.0-dev.2/skill
npm run install:skill -- /absolute/test-skills/make-product-icons /absolute/test-backups outputs/release-0.1.0-dev.2/skill
npm run check:installed -- /absolute/test-skills/make-product-icons outputs/release-0.1.0-dev.2/skill
```

检查退出码：0 匹配，2 未安装/内容不匹配，1 调用或构建失败。安装损坏候选会失败，不替换原安装；相同 build ID 不重复安装，替换前保留备份。安装不启动服务，不更新已运行核心，也不删除数据。

只有用户明确要求本机实际更新时，才将测试安装目录换成 Agent 的真实 Skill 目录。先确认旧实例归属，按需精确停止旧实例；使用新启动回执 URL，检查 `/health`、页面版本/build ID、重开、导出。只清理本轮独占进程；`reused:true` 的既有服务保留。

回退时停止确切属于该安装的实例，保留失败安装，用安装回执中的明确备份目录恢复。不要回滚或迁移项目数据；旧格式不兼容时保留数据并报告。

## 4. GitHub 发布（需单独授权）

1. 审查当前文件与 Git 历史敏感内容，确认仓库可公开、发布范围和版本；完成测试及候选验收。记录候选对应 commit，不混入未提交内容。
2. 提交代码、创建对应版本 tag 并推送，均使用中文维护说明。不要让 GitHub CLI 自动从未知默认分支创建 tag。
3. 创建 Release 草稿，上传**已验收候选**的 ZIP、release.json、sha256.txt。开发版本使用 prerelease。参考：

```sh
gh release create v0.1.0-dev.2 outputs/release-0.1.0-dev.2/make-product-icons-0.1.0-dev.2.zip outputs/release-0.1.0-dev.2/release.json outputs/release-0.1.0-dev.2/sha256.txt --repo walnut-a/boplet-icon-studio --verify-tag --draft --prerelease --title 'Boplet 0.1.0-dev.2' --notes-file /absolute/发布说明.md
```

4. 审核草稿后再发布。用无 GitHub 登录凭据的请求实际下载 ZIP，核对 SHA-256，再在隔离目录安装、启动并导出合成图标。仓库公开、Release 可下载、安装可用分别验收。

不在本流程中加入 `npm publish`。GitHub 的自动 Source code ZIP 不是构建好的 Skill ZIP。

## 5. 官网发布（需单独授权）

GitHub Release 已可下载后，复用原候选准备网页，使用新输出目录避免混入旧下载包：

```sh
npm run prepare:web -- --skill-release outputs/release-0.1.0-dev.2 --output outputs/web-0.1.0-dev.2
```

这是构建，不会上传。确认该目录中的 `/downloads/release.json` 与 GitHub 清单的版本、build ID、文件名、大小及 SHA-256 一致、`/skill/` 与候选一致，然后用 Cloudflare CLI 显式指定该 assets 目录部署。仓库改名后，官网索引的仓库名和下载 URL 使用当前名称；原候选及已发布附件保持不变，历史包内的旧链接由 GitHub 重定向。沿用仓库 wrangler.jsonc 的域名配置，记录实际 CLI 版本与部署 ID；不从过时的个人缓存路径复制部署命令。

线上复查 `/`、`/studio/`、`/skill/SKILL.md`、`/downloads/release.json` 及清单指向的匿名下载；浏览器检查复制指令、语言选择、工作区打开。网页回滚与 Skill Release 回滚分开：网页可回滚到上一部署，安装包仍保留原版本，不覆盖原 tag 的附件。

GitHub 首次发布前，`npm run prepare:web` 可继续生成站点托管的完整预览包，但不代表正式分发方案变回网站或 npm。

## 发布验收记录

### www 域名入口

`www.boplet.app` 使用独立 Worker `boplet-www`（`wrangler.www.jsonc`），将 HTTP/HTTPS 请求以 308 永久跳转到 `https://boplet.app`，保留路径和查询参数。Custom Domain 管理 DNS 与证书；主站的静态资源部署不受影响。

修改跳转逻辑后运行 `node --test tests/unit/www-redirect.test.js`，取得部署授权后使用 `wrangler deploy --config wrangler.www.jsonc`。单独部署此入口不需要重建或上传官网、Skill 包。

每次在唯一开发账本记录：commit/tag、Node/CLI 版本、测试及真实页面结果、候选目录、version/buildId/ZIP SHA-256、实际安装与备份位置（公开文档脱敏）、GitHub 可下载证据、Cloudflare 部署 ID、保留或结束的服务。未完成项明确标出。
