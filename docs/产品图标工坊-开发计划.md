## 1. 实施结论

分为两个交付阶段：**先完成可独立使用的 Skill，再发布共用核心的网页版。**

阶段一内部先交付一条最小但真实的完整流程：空目录 → 草稿项目 → 聊天补充需求 → 确认 → 首个方案 → 登记图标与变体 → 生成 → 容器查看 → 导出 → 重新打开。随后补齐规模维护、全部几何操作、任务恢复和发布质量，不能把这条最小流程当成完整版本提前交付。

WebMCP 和无 WebMCP 的本地入口从第一个可执行工作包起共用操作定义与业务实现；网页端文件适配后置，浏览器可运行的核心设计前置。

```text
A0 合同与工程骨架
 → A1 共享核心、文件存储、本地运行基础
 → A2 首个项目的完整设计流程
 → A3 完整图标系统维护能力
 → A4 Skill 打包与两条路径验收
 → 阶段一交付
 → B1 浏览器本地目录适配
 → B2 无本地服务的在线运行
 → B3 首次安装引导与 Skill 更新分发
 → B4 双端接续、部署验收
 → 阶段二交付
```

默认由当前 Agent 顺序实施，不将启动子 Agent 或多人并行作为计划前提。这里的“多个 Agent 场景”是产品验收场景，可用两个测试客户端复现，不意味着自动创建开发子任务。

## 2. 不可改变的实施边界

| 已确认要求 | 开发中必须体现 | 禁止偷偷加回的实现 |
| --- | --- | --- |
| 先安装并加载 Skill，再选择入口 | 安装/加载就绪是正式工作流起点，Skill 给出标准操作说明 | 让模型从零研究全部 MCP；把下载 ZIP 算作安装完成 |
| WebMCP 优先，不是门槛 | 同一操作定义同时接 WebMCP 和本地内部接口 | 无 WebMCP 只能预览；另造功能缩水版 |
| 在线不运行本地服务 | 核心可在浏览器执行，浏览器直接读写授权目录 | 公网页面绕回 localhost；把 Python 文件 API 暴露到公网 |
| 数据与容器分离 | 项目写入用户目录，安装包只有程序和规范 | 打包真实 HETAO 项目、日志、令牌或缓存 |
| 多项目 → 多方案 → 图标 → 变体 | 显式身份和目录边界，方案默认不混排 | 将旧 `projectKey` 继续冒充项目 ID |
| 只封存，不迁移 | 新版本新建数据，旧目录保持原样 | 旧 ID 映射、旧 URL 适配、项目格式转换器 |
| 后保存生效 | 同一目标最后一次成功写入的内容生效 | 项目占用、租约、`expectedRevision` 拦截、自动合并、冲突裁决 |
| 无手工设计表单 | 聊天写需求；容器负责查看、状态与审核 | 新建项目填写表、手工几何编辑器、容器内聊天产品 |
| 下载/导出可手动点击 | 工具与按钮调用相同交付能力 | 只剩工具、按钮入口被误删，或单项导出下拉 |
| 检查 Skill 更新 | 自动检查、可查询、去重提醒、不自动安装 | 常驻更新守护进程、强制升级、自动覆盖当前包 |
| 轻量、可本地离线 | 本地运行资产随包携带，不依赖 CDN | 云端业务数据库、账号系统、多人协同平台 |

## 4. 工程组织与接口划分

### 4.1 独立开发目录

独立 Git 仓库已按用户指定移至 `<USER_HOME>/GitHub/icon-studio`，作为下一版单一工程。后续直接在仓库根目录实施，不再创建嵌套的 `icon-studio/`。下面是目标结构；当前已创建 contracts/core/storage、合成测试和合同构建入口，其余按工作包逐步建立。旧候选包保持原样，避免改到正在使用的预览来源。

```text
icon-studio/
  README.md                    # 安装、开发、构建、测试和支持环境
  package.json                 # 一个工程，不拆成多个发布包
  src/
    contracts/                 # 数据 schema、操作定义、错误、能力清单
    core/                      # 项目、需求、方案、任务、几何、审核、导出
    storage/                   # 接口 + memory/node/browser 适配
    runtime/                   # 本地服务、启动器、浏览器 Worker
    transports/                # WebMCP 注册、本地内部操作分发
    app/                       # 一个 HTML 应用入口、路由、组件、样式
  skill/
    SKILL.md
    references/                # 标准操作、格式、设计方法、两条完整示例
  tests/
    unit/
    contract/
    integration/
    e2e/
    fixtures/                  # 仅合成数据和模拟发布清单
  scripts/                     # 构建、测试、打包；不是业务 CLI 产品
  release/                     # 版本与发布资产模板，不放用户项目
```

候选产物输出到 `outputs/icon-studio-next/skill/` 与 `outputs/icon-studio-next/web/`，由同一版本构建生成。打包时技术调用名仍是 `make-product-icons`，不因开发目录名另造一个 Skill。安装/正式部署放在交付门槛之后单独执行，不覆盖现有全局安装来验证开发中间态。

### 4.2 关键实现约束

- 采用需求文档确定的 JS/TS 共享核心、本地 Node 运行时、浏览器 Worker。具体受支持运行时和构建依赖在 A0 固定并记录；不在计划中臆测未来最低版本。
- 不强制引入新的 UI 框架，优先保留现有原生组件。核心不导入 DOM、Node 文件 API 或浏览器目录句柄；这些依赖留在适配层。
- `operations` 是唯一可执行操作定义源：参数 schema、结果 schema、注解、处理函数、工作流阶段和权限需求均在这里。WebMCP 与本地内部接口只做传输适配。
- 本地接口基线为读取能力目录、调用具名操作、读取会话上下文三类入口。Agent 按 Skill 示例用宿主已有 HTTP/执行能力调用，不新增业务命令行应用或 MCP 服务器。
- `Storage` 只提供授权范围内的读取、枚举、完整文件写入和基本文件操作；不加入 acquireLock、compareAndSwap、merge 等方法。
- `sourceRevision` 只用于说明来源；内容哈希用于预览缓存/审核关联，不作为“别人改过所以拒绝保存”的检查。
- `expectedContextId` 只识别本会话用户指的是哪个对象。另一个 Agent 写了同一文件不导致项目独占或冲突拒绝；目标已不存在仍返回正常的目标错误。
- 确认记录绑定用户确认的内容，不伪造“确认过新内容”。正常更新 brief 不因为另一会话存在被禁止。
- 多文件提交只报告逐项结果，不建设跨文件事务或全局事件流。单会话可去重，同目录跨进程不承诺恰好一次执行。

## 5. 阶段一工作包：完整 Skill

所有工作包初始状态均为“未开始”。每个工作包只有取得所列证据后才能标记完成。

### A0：工程骨架、数据与操作合同

**交付**

- A0.1 建立上述工程、README、构建和非 watch 测试入口；记录依赖许可证与支持环境。
- A0.2 固定 Library/Project/Scheme/Icon/Variant、brief、rules、task、review、delivery 的 schema，区分项目身份、方案身份和内容版本。
- A0.3 建立具名操作注册表、统一结果与错误；按需求 §11.2 覆盖所有能力，不仅列工具名称。
- A0.4 建立 memory Storage 与合成夹具生成器：空库、零方案项目、两个同名但不同身份项目、多方案、不同尺寸/样式/轻重。
- A0.5 明确当前版本格式，不支持旧格式；用测试禁止项目锁、旧 ID 别名和基础版本拦截进入新写入链。

**先写的失败测试**：空项目可序列化；项目/方案 ID 不混用；非法嵌套字段拒绝；来源版本较旧不是写入错误；返回 schema 能表达实际失败。

**完成证据**：构建与合同测试可运行；操作覆盖表没有未登记能力；新目录不触碰旧项目；没有凭空宣称线上或安装可用。

### A1：共享几何基础、本地存储与运行入口

依赖 A0。

**交付**

- A1.1 先验证高风险几何：路径节点/控制柄、曲线极值与墨迹边界、圆角、布尔运算；再补基础图形。需要算法依赖时只选择可在 Node/Worker 同用、许可证可分发的实现；不维持两套生产引擎。
- A1.2 实现 Node Storage：默认系统文稿位置、用户自选/当前目录、配置与项目分离、完整文件写入、不兼容格式识别。
- A1.3 实现内置启动器：检测和复用本任务服务、动态端口、版本与健康回执、明确退出/保留规则。启动器不自动载入或改写旧 HETAO 项目。
- A1.4 提供薄本地服务、受控内部调用和 WebMCP 适配骨架；安全保留回环地址、Host/Origin、会话凭据、路径与请求大小限制。
- A1.5 加入会话内操作状态和有界事件读取；取消只针对指定会话/操作，不关闭其他用户会话。

**先写的失败测试**：拒绝越界路径与未授权读取；保存失败返回 failed；两个客户端顺序覆盖同一目标，第二个旧副本成功并生效；几何边界与实际输出一致；空目录可以启动。

**完成证据**：同一核心能在 Node 和浏览器测试环境运算合成几何；本地服务从空库运行；两条入口对同一操作得到同构结果；无项目占用机制。

此处浏览器环境仅验证共享核心能运行，不提前完成线上部署或浏览器文件存储。

### A2：从空项目到单图标交付的纵向流程

依赖 A1。这是第一个可供用户完整体验的开发里程碑，不是完整 Skill 发布。

**交付**

- A2.1 项目创建/列表/读取/打开/更新；零方案是正常状态；页面默认不抢走当前浏览目标。
- A2.2 聊天写 brief、来源分类、缺项检查、确切内容确认；需求页只展示信息，不增加表单。
- A2.3 建立首个方案，不需要 sourceSchemeId；登记语义、tags、用途、变体与首批任务。
- A2.4 使用共享核心写入一个合成图标、校验、编译；明确区分 draft、compiled、review 与 persisted。
- A2.5 接入现有 HTML 外观：项目库 → 项目 → 方案列表 → 图标详情；显示最新预览、图层/节点选区。
- A2.6 下载 SVG 和导出按钮与工具共用执行逻辑；重新打开能读到保存的项目。
- A2.7 同步编写 Skill 的“从空目录开始”示例，分别列出 WebMCP 和本地调用顺序，不等最后才补说明。

**先写的失败测试**：未确认需求不能生产；空项目能建首方案；用户在聊天补充后页面相同字段更新；图标用途与尺寸变体不混淆；工具与按钮导出同一版本；重开不重复创建项目。

**完成证据**：同一个合成用例分别通过 WebMCP-only 与禁用 WebMCP 的本地调用走完，保留操作记录、磁盘结果和真实页面截图。

### A3：完整维护链与大图标库

依赖 A2。按下面顺序推进，每组完成即接入两条入口与现有页面。

| 顺序 | 工作包 | 关键验收 |

| A3.1 | 项目/方案归档恢复、方案复制、规则确认、偏好方案；来源资料读取 | 复制是独立实现；原目录授权不延伸至其他目录；查看不等于采用 |

**完成证据**：完整工具覆盖测试、真实任务恢复记录、600 图标夹具下的查询与渲染测量，以及既有 UI 设计回归截图。

**阶段一门槛**：A0–A4 均完成，才标记“完整 Skill 可交付”。合成发布源测试只能证明检查逻辑；真实更新源尚未部署时必须标记尚未接通，不声称自动更新提醒已在线运行。

## 6. 阶段二工作包：直接在线使用

阶段二只增加浏览器存储、运行装配、首次使用与发布环境，不复制业务实现。阶段一通过后再开始正式阶段二；A1 的浏览器核心测试不算网页版交付。

### B1：浏览器目录存储

- 实现与 Node Storage 同合同的目录句柄适配，用户交互完成授权，清晰报告 pending/granted/denied/cancelled。
- 默认目录只是选择建议，不能静默代替用户授权；句柄与偏好可存在浏览器，正式项目必须在用户目录。
- 重开、重新授权、更换目录、清站点数据后重新选择原目录，按 libraryId/projectId 找回内容。
- 无目录 API 或权限失败不转存隐藏缓存；引导使用已安装 Skill 的本地容器。
- 完整文件写入和失败回报；多窗口不加占用或基础版本门槛，遵守后成功保存生效。

**完成证据**：对同一合成项目，Node 与浏览器适配读到相同数据；浏览器实际授权、取消、撤权和重连录像/截图及结果记录。模拟句柄单测不能代替真实权限验收。

### B2：不依赖本地服务的在线容器

- 从同一源构建静态站点，Worker 执行核心，浏览器 Storage 落盘。
- WebMCP 使用相同操作定义；本地内部 HTTP 入口不打包进在线执行依赖。
- 检查页面、网络和进程证据：在线流程没有启动 localhost，也没有发送项目数据到网站后台。
- 原生 WebMCP 不可用时说明实际能力并转本地；不安装伪造的 API、不用页面自动点击补齐业务。

**完成证据**：测试环境仅提供静态资源，完成项目创建至导出；在线调用和本地调用对合成输入产出一致；浏览器主线程在大库读取/编译时仍能响应导航。

### B3：先安装 Skill 的首次使用与分发

- “开始设计”入口提供标准宿主指令，先安装/加载 Skill，再选择在线或本地。不以页面猜测本机文件代替安装证据。
- 完整 Skill 包、版本、校验值、标准说明随站点提供。已安装且可用则复用，不每次重装；不静默覆盖用户现有安装。
- 初始只读引导可返回安装来源、要求版本和状态；正式操作在 Skill 就绪后开始。宿主转述必须标明证据来源，不包装成人类签名或强安全认证。
- 将 A4 的更新能力连接真实固定发布清单；清单与下载包版本/哈希保持一致，旧源失败有明确状态。
- Skill 已加载的在线用户不启动本地服务；在线出现问题才按用户选择启用本地。

**完成证据**：一个未安装用户的完整在线开始流程；一个已安装用户复用流程；没有 WebMCP 的用户转本地完成全流程；不支持自动安装的宿主有明确下载/加载步骤，而不是死循环重试。

### B4：双端接续与部署验收

- 在线保存 → 本地选择同一目录继续 → 在线重新读回；保留项目/方案/图标身份，不复制、不导入、不迁移。
- 正常顺序接续验证已保存内容；异常退出只恢复已完整落盘的数据，不承诺找回内存草稿。
- 两端同时打开、先后写入同一文档，后保存生效；不要求释放旧会话，也不承诺字段合并或跨文件全局顺序。
- 静态资源和 Worker 使用明确构建版本，避免旧 HTML 加载新核心；程序回滚遇到不支持的格式只拒绝写入，不转换数据。
- 检查 HTTPS 部署、目录授权所需环境、CSP、下载链接、发布清单与缓存策略；不得增加账号或云端项目服务。

**完成证据**：双端接续报告、两个入口的实际文件内容、发布资产清单、真实站点冒烟、版本不匹配测试和可执行的程序回滚记录。

**阶段二门槛**：B1–B4 均通过且实际部署完成，才宣称网页版上线。测试站点通过、本地构建完成、公开网站上线分别记录。

## 8. 测试与验收执行方式

### 8.1 TDD 和增量验证

可自动化行为先写失败测试，再做最小实现。每个工作包验证本次变化和依赖回归，不为每次文案调整重跑所有环境。纯文案/静态规范改动做文档与真实界面检查，不机械制造测试。

| 层次 | 覆盖 | 不可替代的证据 |
| --- | --- | --- |
| 单元 | schema、几何、状态、导出、更新比较与缓存 | 数学断言、合成期望值、失败分支 |
| 合同 | 每个操作的输入/输出/错误，两条入口映射 | 自动检查目录/处理函数/schema 完整一致 |
| 存储集成 | 读写、取消、无权限、失败、后写覆盖、格式不兼容 | 实际文件与操作结果对照，不只 mock 返回 success |
| 流程集成 | 新建→确认→生产→审核→导出→重开 | 分步执行记录、内容版本和文件产物 |
| WebMCP-only | Agent 业务仅使用 WebMCP | 不用本地 HTTP、DOM 或截图调用补缺失业务工具 |
| Skill 回退 | 禁用 WebMCP，只按包内规范使用本地入口 | 不逆向 UI，不要求用户手工代填需求 |
| 浏览器视觉 | 页面、控件、焦点、选区、场景、窄屏、中英文 | 真实运行截图/交互记录，不以 CSS 值相同代替对齐验收 |
| 分发/离线 | 新安装、断网、包扫描、版本/下载、双端接续 | 干净安装位置、网络记录、文件清单、哈希 |

### 8.2 必测的简单覆盖语义

两个客户端都读取 A 版；客户端一保存 B；客户端二仍以 A 为来源保存 C。目标磁盘最终必须是 C，第二次不得收到项目占用或版本冲突拒绝。刷新客户端一后能读到 C。C 覆盖 B 是已确认行为，不记录为需要修复的“丢失更新”。

测试不扩展为全局顺序或多文件事务测试平台。文件 API 自己失败时必须报错，不能把失败当成“后写获胜”。

### 8.3 规模和视觉质量

- 合成数据规模：20 项目、每项目 5 方案；选定压力方案生成 600 图标、每图标最多 4 个登记变体。另验证全库索引不触发所有几何编译。
- 默认页 48、工具最大页 100；记录未打开项目的编译调用数应为零。
- 在明确设备和缓存条件下测查询/分页 p95 ≤ 300ms、缓存详情切换 ≤ 200ms、长任务 1 秒内返回 operationId。不把示例只有两张图标当作性能通过。
- 保留黑白灰、统一控件、标题对齐、方案导航、图标平铺到详情、固定场景、没有常驻“已保存”及没有评价文案。
- 真实验收至少覆盖桌面宽屏、窄窗口、键盘操作和中英文；浏览器/宿主/OS 版本写入记录。

### 8.4 未来工程测试入口

A0 建立并在 README 固定 `test:unit`、`test:contract`、`test:integration`、`test:e2e`、`build`、`pack:skill`、`build:web`、`check:package` 这些非 watch 入口。这里是建设任务，不是现在可以直接运行的命令清单。

现有 `work/test_*.mjs` 和 `work/test_*.py` 可提供回归语义；旧合同测试不强制继续全绿。保留数学与 UI 行为要求，删除仅用于证明旧别名、旧锁和旧版本拒绝机制的断言，并用新需求测试替换。

## 9. 风险与处理顺序

| 风险 | 何时验证 | 处理原则 |
| --- | --- | --- |
| 曲线/布尔/描边几何在共享实现中不一致 | A1 最先验证 | 先合成数学用例；不双引擎兜底、不删能力；若确实无法满足，报告具体阻碍而非自行降级需求 |
| 新旧项目身份混用 | A0/A2 | 新 schema、新操作版本、新数据，拒绝旧格式，不造迁移层 |
| 旧并发保护被顺手复制 | A0/A1/A3 | 操作与存储负向测试，确保不要求基础版本、不占项目 |
| 大库分页只是 UI 装饰 | A3.8 | 检查数据枚举/编译调用量，再做计时 |
| 本地回退只有生成没有完整维护 | A2/A4 | 单独禁用 WebMCP 验收全部流程 |
| 浏览器目录授权不能静默完成 | B1 | 清楚展示系统权限动作、状态可读；不隐藏保存到缓存 |
| 网页误判 Skill 已安装 | B3 | 区分下载、安装、加载及其证据，不构造万能安装 API |
| 更新发布源或域名还没有配置 | A4/B3 | 先用合成源测试，正式发布时注入确切 URL；未连真实源就不声称可在线检查 |
| 打包混入真实数据 | A4/B3 | 白名单构建与包内容扫描，不从整个工作目录打 ZIP |
| 本地/在线版本不一致 | B4 | 核对格式和运行版本，拒绝不支持的格式，不迁移 |

实际域名、发布账号、Windows 验收设备和目标宿主是交付环境资源，不是重新待定的产品需求。对应阶段到达时验证可用性；缺少资源则明确标记该项未验收，不以 mock 代替，不阻碍前面的可执行工作包。
