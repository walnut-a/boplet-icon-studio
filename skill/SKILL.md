# Boplet — Icon Studio

先完整读取本文件，再开始操作。以对话澄清需求、登记计划、修改图标；HTML 用于看项目、方案、结构、应用场景和真实执行状态。用户可以导航、选择节点和下载，不在容器手填需求或拖动几何。不要在界面加入内部设计推理、评分、风险评价或常驻“已保存”。

## 开始之前

**启动前必须先征得同意**：向用户说明并询问：“此 Skill 必须通过本地或在线 HTML 页面作为中介运行，用于展示需求、方案和图标。是否允许？”等待明确答复；拒绝或未回答时不启动、不复用服务，也不绕过容器直接生成文件。安装、目录授权或用户泛泛要求设计图标不等于这项同意。记录本次答复引用；同一连续任务内已经明确同意且未撤回的，不因技术重启反复询问。新的独立调用重新确认。

同意后才能启动/连接容器，并实际打开绑定当前会话的页面。没有可用的 HTML 页面时暂停设计并说明原因；Agent 不具备浏览器操作能力时可请用户打开，不能伪造页面连接。用户关闭或撤回同意后，不继续新的设计操作，应先恢复页面或结束本次使用。HTML 是必需中介，WebMCP 是优先传输，两者不能混为一个门槛。

1. 读取包内 `version.json`。本包格式与合同都是 v3；未知旧格式只保留，不转换、映射或迁移。不修改全局其他 Skill 或旧项目。
2. 读取 [运行与恢复](references/runtime.md)，确认本次用户授权的数据目录。首次给出系统文稿目录下 `Codex/Icon Projects` 的默认建议，也可使用当前目录或用户另选目录。**路径建议不是授权**。记住选择后不反复询问。
3. 安装和加载分开判断：文件落地是安装；当前 Agent 读完本文件和所需规范才是加载。启动器的加载声明是宿主转述，不是加密验证。
4. 先走支持原生 WebMCP 的容器；没有 WebMCP 仍可在 HTML 页面保持打开的前提下通过同一包的本地调用完整工作，不把 WebMCP 当使用门槛。网页来源/目录权限不可靠时切换本地容器，重新授权同一数据目录；不要复制业务数据进 HTML。

官网为 https://boplet.app，在线工作区为 https://boplet.app/studio/。用户自行查看和导出已有项目不需要 Agent 或 Skill 加载；Agent 开始设计前仍须完整加载本 Skill 并取得 HTML 同意，再按运行规范使用原生 WebMCP 声明就绪。目录由用户直接选择或重新授权，不让 Agent 反复导入数据。在线设计不可用时使用包内本地容器，不让公网页面调用 localhost。

## 规范与工具

- 设计前读取 [设计方法](references/design-method.md)。进入修改前读取 [数据与维护](references/data-and-maintenance.md)。
- 两条完整路径见 [流程示例](references/workflows.md)。本地标准请求见 [运行与恢复](references/runtime.md)。
- **`contracts.json` 是工具输入、输出和数据结构的唯一机器合同**；运行中的 `get_capabilities` 返回同一份合同。按本文件给出的流程定位业务操作，再读取单项 schema，不要求宿主一次加载完整目录。不要自造旧工具名或混用 `projectKey`。
- WebMCP 固定使用 `icon_studio_v3_get_workflow`、`list_operations`、`get_operation_schema`、`read`、`write` 五个网关：先读取业务操作 schema，再按 `readOnly` 走读或写网关。本地 `/operation` 仍使用不带前缀的业务操作名。两条传输共用核心、校验和落盘，不实现两套几何引擎。
- 合同失败时报告业务操作、字段路径、Skill 版本和 build ID；旁路磁盘诊断不能冒充具名操作成功，也不能据此修改或交付数据。
- 每个写操作提供新的 `requestId`。网络回执不确定时只重试原 ID 和原参数；过期先读状态。`sourceRevision` 说明来源，不是锁；同一目标最后成功保存生效。原则上不建议多个 Agent 同时改同一项目，但不阻止用户这样使用。
- 用户说“这个”“选中的”时，先读 `get_view_context` 和 `get_selection`，传回 `expectedContextId` 与明确身份；没有选择就不能猜。场景页面不具有隐藏的结构节点选区。
- `accepted` 只表示已受理，继续用 `get_operation` 等最终回执；`waiting_user` 等用户授权/确认；`failed` 不宣称完成。批量逐项结果中有失败就如实报告。保存、验证、编译、用户接受和导出不是同一状态。

## 工作顺序

**命名风格**：创建或重命名项目、方案、图标时，不使用中点 `·` 拼接名称。名称直接表达对象，必要的编号或补充词用空格连接，例如“产品名 图标设计”“A 内庭”。此规则只约束名称，不限制尺寸、样式等说明文字的分隔符；已有名称不批量改写，用户明确要求改名时再通过对应操作保存，不在 HTML 中临时替换字符。

1. **项目库**：连接目录 → 列表/打开或创建项目。可以平行有多个项目，每个项目有多个独立方案。不得把方案当项目。
2. **需求**：在聊天中询问设计目的、风格偏好、用户、使用场景、范围、约束。目的说明为什么设计、解决什么问题；风格偏好记录用户的审美倾向，无偏好可写不限定。Agent 提出的具体造型属于方案探索，不提前写成需求；用户明确指定的造型则作为有来源的约束。用 `update_brief` 写入，逐字段记录用户来源、资料来源或待确认推断；页面同步展示，无需让用户再说“表单填完”。
3. **确认**：`validate_brief` → `prepare_confirmation` → 把返回的确切摘要展示给用户 → 用户确认后 `confirm_brief`。内容变化需要重新准备确认，不代替用户确认。用户确认需求后直接进入首轮图标生产，不再为方案方向、网格、描边或圆角增加二次确认；只有需求范围或明确约束需要改变时才追问。
4. **方案**：确认需求后 `create_scheme`，由 Agent 用 `set_design_rules` 制定并保存绘制规则；复制方案也由 Agent 检查并保存独立规则。第一方案不需要来源。不同方案明确隔离，左侧按名称自然升序切换，不混排图标。创建方案只是连续生产中的内部步骤，不能停在空框架要求用户确认；应完成首轮图标与预览后交给用户看图反馈。
5. **图标系统**：先登记语义名称、concept、实际 tags、用途；“主图标”和“状态栏”是不同用途对象，不默认当一个图标的尺寸变体。尺寸/填充描边/轻重属于同一语义图标的独立变体。
6. **生产**：保存规则 → 登记变体和明确目标批次 → 启动任务 → `apply_operations` 写显式图层/节点/组件 → `validate_icon` → `compile_scheme`。先完成代表性图标供用户看图反馈，再分批扩展。没有任务不能直接生产；规则 ready 只表示可用于生产，不是用户确认或接受。
7. **选择主线与修改**：看过方案后，在合适时机轻声询问“是否将某方案作为后续细化的主方案？”，不反复催促，不将此问题作为继续绘制或导出的关卡。“倾向”“喜欢”、切换查看、请求优化都不等于确认。用户明确选择后调用 `set_primary_scheme`，附真实答复引用；页面只给主方案显示“已确认”，其他方案适度淡化且仍可编辑。不显示“待审核／需修改／待复核”，不要求逐图标审核。确认的是设计方向，修改图标不取消主线。用户可切换主方案或以 schemeId:null 取消；默认不归档、不删除其他方案或数据。`get_project`、`open_project`、`get_view_context` 直接返回主方案 ID、名称、确认时间，优先利用已有上下文，不反复单独查询。修改仍保存用户原文反馈、登记任务、校验和编译。
8. **交付**：明确项目/方案/图标/变体范围，`prepare_export` → 最终 `get_export` → `read_artifact`。SVG 必须与当前编译哈希相符。按钮使用同一流程；源快照不等于迁移包。
   **交给其他 Agent**：工具和“复制给 Agent”按钮共用 `get_agent_handoff`。方案列表复制 scope:scheme；结构详情复制 scope:variant；应用场景复制 scope:icon，不暗带尺寸选区。指令包含授权目录、确切 ID、主线信息和源定位，不包含令牌或临时端口。草稿／备选也可交接，不自动确认。接收 Agent 先加载 Skill 并遵循 HTML 同意流程，获本地权限后读取当前源与 SVG；哈希是复制时快照，内容变化时说明，不回退新修改。不擅自改动源项目。跨设备或无权限时请求目录访问或导出文件，不假装已读取。
9. **恢复与更新**：重新调用先连接原目录、读项目/任务/恢复状态，不重复建项目。启动及使用过程中非阻塞检查 Skill 更新，最多复用 24 小时成功缓存。工具可显式重查；未知版本或网络失败不报告“最新版”。不自动安装、不替换运行核心、不迁移旧项目。

## 完成判断

完成应有当前磁盘回执、对应编译/导出内容和真实容器观察。截图只是显示证据，不能证明安装、部署或用户审核已经完成。不能把测试中合成的用户确认拿来当真实用户确认。
